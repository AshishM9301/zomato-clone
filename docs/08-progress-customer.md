## Auth model
- JWT in **`react-native-keychain`** (Android Keystore-backed; not readable by other apps).
- The web's httpOnly cookie path is **browser-only** — RN uses `Authorization: Bearer <token>` on every protected request, matching the smoke script's pattern.
- Auth bootstrap: on app start, `AuthContext` reads the token from keychain; if present, calls `GET /auth/me` to validate it and load the user; if absent or 401, shows the login screen.
- `useAuth()` exposes `{ user, status, requestOtp(phone), login(phone, otp), logout() }`.
- `UNAUTHENTICATED` responses clear the token from keychain and bounce to login (via a `onUnauthorized` listener registry, since Hermes lacks a global `EventTarget`).
- `logout()` calls `POST /auth/logout` (idempotent; backend also clears its cookie, which we ignore), then clears local state and storage.

## OTP flow (dev)
- Backend `POST /auth/customer/request-otp` returns `{ sent: true, devCode?: "123456" }` — the `devCode` is only present outside production.
- The customer app reads `devCode` from the response and shows it in an `Alert` so the user can type it. In production, the OTP would arrive via SMS from Twilio / MSG91 (open question — see `03-open-questions.md`).

## API client (`src/api/client.ts`)
- Base URL: `Config.API_BASE_URL` from `react-native-config` (`.env`). Default: `http://10.0.2.2:4000/api/v1` (emulator) or `http://<LAN_IP>:4000/api/v1` (USB device).
- `fetch` called with `Authorization: Bearer <token>` from keychain on every request.
- Decodes the backend envelope `{ success, data | error }`.
- On `UNAUTHENTICATED` (401): clears the token from keychain and emits `onUnauthorized` the auth context listens to.
- Throws `ApiError` with `{ code, message, status, details }`.
- Helpers: `api.get<T>(path, query?)`, `api.post<T>(path, body?)`, `api.patch<T>(path, body?)`, `api.del<T>(path)`.

## Endpoints consumed
| Surface | Endpoint | Notes |
|---|---|---|
| Auth | `POST /auth/customer/request-otp` | `{ phone }` → `{ sent, devCode? }`. |
| Auth | `POST /auth/customer/verify-otp` | `{ phone, otp }` → `{ token, user }`. First-time OTP creates the customer. |
| Auth | `GET /auth/me` | Bootstrap probe on app start. |
| Auth | `POST /auth/logout` | Idempotent. |
| Browse | `GET /restaurants?q=&page=&limit=` | Optional search (debounced 300ms client-side). |
| Browse | `GET /restaurants/:id` | Restaurant metadata. |
| Menu | `GET /restaurants/:id/menu?include_unavailable=false` | Menu items; unavailable filtered out client-side as well. |
| Orders | `POST /orders` | `{ restaurant_id, items: [{ menu_item_id, qty }], address, lat?, lng?, notes? }` → `{ order, items }`. **No idempotency key** — see `03-open-questions.md`. |
| Orders | `GET /orders` | Customer-scoped list. |
| Orders | `GET /orders/:id` | Polled every 5s on the detail screen. |
| Orders | `POST /orders/:id/cancel` | `{ reason }`. Only allowed from `placed`. |

## Endpoints NOT used (intentionally)
- All `/merchants/*`, `/riders/*`, `/admin/*`, `/users/*`, `/dispatch/*` — staff/internal.
- The `?near=lat,lng` query param on `GET /restaurants` — no geolocation in v1.
- The `?include_closed=true` query — the customer only sees open restaurants.

## Cart
- A single-restaurant cart (one restaurant at a time; adding an item from a different restaurant clears the cart with a confirmation alert).
- Each line: `{ menu_item_id, restaurant_id, name_snapshot, unit_price_cents, qty }`.
- Persisted to AsyncStorage under key `zc.cart.v1`; survives app kills.
- `useCart()` returns `{ items, restaurantId, add, setQty, remove, clear, subtotalCents, wouldReplaceRestaurant }`.
- Delivery fee (3000 paise) is shown in the cart total client-side; the backend also adds it server-side.

## Live tracking
- `OrderDetailScreen` polls `GET /orders/:id` every 5s via `useQuery({ refetchInterval: 5_000 })`.
- Cancel button appears only when `status === 'placed'`. Tap opens a tiny inline `Modal` with a `TextInput` for the reason (validated by `cancelReasonSchema`). On confirm, the order list and detail are invalidated.

Manual walk-through:
1. Launch → Login screen.
2. Enter phone (e.g. `9999999999`) → tap **Send code** → alert shows `devCode` from the backend (e.g. `123456`).
3. Enter OTP → tap **Verify** → land on **Browse** tab.
4. Tap a restaurant → menu opens → tap **+** on 2 items → tap **Cart** tab.
5. Enter an address → tap **Place order** → land on **OrderDetail** showing `placed` status.
6. Wait 5s — the status pill polls and refreshes.
7. (Optional) tap **Cancel order** → enter a reason → confirm → status flips to `cancelled`.
